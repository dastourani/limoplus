# اگر دقیقه‌های Actions تمام شد (یا حساب عوض شد)

GitHub Actions در ماه ۲٬۰۰۰ دقیقه‌ی رایگان می‌دهد و لیموخوان بیشترش را خرج می‌کند: تست‌ها، هر APK حدود ۳۵ دقیقه، و
هر انتشار روی «deploy» چند دقیقه. با تمام شدن آن، هیچ ورک‌فلویی **شروع نمی‌شود** (نه اینکه تست‌ها خطا بدهند) — یعنی
سرور هم به‌روز نمی‌شود و APK تازه هم ساخته نمی‌شود. پیامش در صفحه‌ی Actions این است: «The job was not started because
recent account payments have failed or your spending limit needs to be increased».

## راه‌های گذر از این وضعیت، ارزان به گران

| راه | هزینه | چه چیزی درست می‌شود |
| --- | --- | --- |
| **مخزن را عمومی کنید** (Settings › General › Dangerous zone › Change visibility) | ۰ | روی مخزن عمومی، دقیقه‌ها **بی‌نهایت** است. `backend/.env` و `app/.env` هیچ‌وقت در گیت نیستند (در `.gitignore`)، پس رمز و شماره‌ی خط و توکن داخل مخزن نمی‌ماند. |
| حساب دیگری بسازید و مخزن را **Transfer** کنید | ۰ | دقیقه‌های همان حساب تازه. انتقال مخزن خودکار است (Settings › General › Transfer)؛ releases و secrets همراهش می‌آیند و هیچ کلید اضافه‌ای در GitHub لازم نیست (`deploy.yml` با `GITHUB_TOKEN` خودش push می‌کند). |
| اجرای محلی به‌جای Actions | ۰ | تست‌ها و build وب روی لپ‌تاپ خودتان (پایین). APK را هم می‌شود محلی ساخت، ولی کند است. |
| خرید دقیقه یا بالا بردن سقف خرج | پول | همه‌چیز مثل قبل. |

## انتقال به حساب دیگر: چه چیزی جابه‌جا می‌شود

۱. در حساب تازه: مخزن را از Settings › General › Transfer بگیرید (مالک جدید باید قبول کند).
۲. Releases (APKها) و secrets همراه مخزن می‌روند. `deploy.yml` توکن جدا لازم ندارد.
۳. **پارس‌پک:** شاخه‌ی `deploy` همان مخزن است؛ اگر پارس‌پک با آدرس قدیمی مخزن دنبالش می‌آید، آدرس تازه را در پنلش
   بگذارید (`docs/deploy-parspack.md`). آخرین push به «deploy» همان آدرس قدیمی است و با آدرس تازه خودش از نو ساخته می‌شود.
۴. اگر مخزن عمومی شد: secrets زنده می‌ماند و ورک‌فلوی‌ها همان‌طور کار می‌کنند.

## چرا تست‌ها «شکست خوردند»؟

متن قرمز «All checks have failed» گمراه‌کننده است: کار **شروع نشده** («The job was not started…»)، نه اینکه کدی خطا
داده باشد. برای همین روی PR #44، همان کد با ۵۰۳ تست روی PostgreSQL محلی سبز بود. بعد از حل دقیقه‌ها، فقط «Re-run
all jobs» لازم است.

## اجرای محلی (بدون Actions)

```bash
# تست‌های بک‌اند، همان که CI اجرا می‌کند
cd backend
SECRET_KEY=test DEBUG=True python manage.py test apps

# نسخه‌ی وب اپ روی لپ‌تاپ
cd app
npm ci
npx expo export -p web        # خروجی در app/dist

# همان چک پنل که مرورگر لازم ندارد (تست‌های پنل فقط HTML را می‌بینند، JS را نه)
npm i --no-save jsdom
node scripts/panel-check.js
```

## اگر نمی‌خواهید مخزن عمومی شود

همان دو کار محلی بالا کافی است: مخزن خصوصی بماند، تست‌ها و build را خودتان بزنید، و APK را از Releases قبلی
بردارید. «deploy» تا وقتی Actions برنگردد به‌روز نمی‌شود — اگر لازم شد، می‌شود همان کامیت deploy را با یک
`git push` دستی از لپ‌تاپ ساخت (همان دستور آخر `deploy.yml`).
