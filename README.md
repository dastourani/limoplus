# لیموخوان

پلتفرم درس تعاملی: کتاب‌های هر رشته به‌صورت خلاصه و جزوه، با تست، فلش‌کارت و آمار مطالعه.

| بخش | پوشه | فناوری |
| --- | --- | --- |
| سرور و پنل مدیر | `backend/` | Python · Django 5.2 · Django REST Framework · PostgreSQL |
| اپ (اندروید، وب‌اپ آیفون و کامپیوتر) | `app/` | TypeScript · React Native · Expo |

## اجرا روی سیستم خودتان

### ۱. سرور (با Docker)

پیش‌نیاز: [Docker Desktop](https://www.docker.com/products/docker-desktop/)

```bash
cp backend/.env.example backend/.env      # بعد SECRET_KEY را در آن عوض کنید
docker compose up --build
```

- سرور: http://localhost:8000/api/v1/health/
- پنل مدیر: http://localhost:8000/admin/

ساخت حساب مدیر (در یک ترمینال دیگر):

```bash
docker compose exec backend python manage.py createsuperuser
```

بارگذاری کتاب نمونه (ریاضی عمومی ۱، با رشته‌ها و بنرهای نمونه):

```bash
docker compose exec backend python manage.py load_samples
```

تا وقتی `SMS_BACKEND=console` است، کد ورود به‌جای پیامک در خروجی همین ترمینال Docker چاپ می‌شود.

### ۱ (راه دیگر). سرور بدون Docker، فقط با Python

اگر Docker نصب یا دانلود نمی‌شود، کافی است [Python](https://www.python.org/downloads/) نسخه‌ی ۳.۱۲ یا بالاتر نصب باشد.
در این حالت داده‌ها در فایل `backend/db.sqlite3` ذخیره می‌شوند و نیازی به PostgreSQL نیست.
پوشه‌ی پروژه را **بیرون از Dropbox/OneDrive/Google Drive** بگذارید (مثلاً `C:\limoplus`)؛ همگام‌سازی این برنامه‌ها می‌تواند فایل دیتابیس را خراب کند.

1. در پوشه‌ی `backend` فایل `.env.example` را کپی کنید و نامش را `.env` بگذارید.
2. `.env` را با Notepad باز کنید و خط `DATABASE_URL=...` را خالی کنید: `DATABASE_URL=`
3. در همان پوشه یک ترمینال باز کنید (ویندوز: در نوار آدرس پوشه بنویسید `cmd` و Enter) و این دستورها را یکی‌یکی اجرا کنید:

```bash
python -m venv venv
venv\Scripts\activate            # مک و لینوکس: source venv/bin/activate
pip install -r requirements.txt
python manage.py migrate
python manage.py load_samples
python manage.py createsuperuser
python manage.py runserver 0.0.0.0:8000
```

دفعه‌های بعد فقط دو دستور لازم است: `venv\Scripts\activate` و `python manage.py runserver 0.0.0.0:8000`.

### ۲. اپ

پیش‌نیاز: [Node.js](https://nodejs.org/) نسخه‌ی ۲۰ یا بالاتر

```bash
cd app
cp .env.example .env
npm install
npm run web        # نسخه‌ی وب در مرورگر: http://localhost:8081
```

برای گوشی از APK بخش ۳ استفاده کنید.

### ۳. نسخه‌ی آزمایشی اندروید (APK)

با هر تغییر در اپ، گیت‌هاب خودکار یک APK می‌سازد (حدود ۱۵ دقیقه). دانلود: صفحه‌ی مخزن در گیت‌هاب › **Releases**
› آخرین «نسخه‌ی آزمایشی» › فایل `.apk`. روی گوشی نصبش کنید (اجازه‌ی «نصب از منابع ناشناس» لازم است).

برای وصل شدن به سروری که روی لپ‌تاپ اجرا می‌کنید:

1. گوشی و لپ‌تاپ در یک Wi‑Fi باشند.
2. آدرس IP لپ‌تاپ را پیدا کنید (ویندوز: دستور `ipconfig`؛ مک: تنظیمات Wi‑Fi). مثلاً `192.168.1.20`.
3. در `backend/.env` خط `ALLOWED_HOSTS=*` را اضافه کنید و سرور را دوباره اجرا کنید (فقط برای تست روی سیستم خودتان).
4. در اپ: صفحه‌ی اول › «تنظیمات سرور» › `http://192.168.1.20:8000` › «آزمایش اتصال» › «ذخیره».

## امکانات پنل مدیر

آدرس پنل با `ADMIN_URL` در `backend/.env` تعیین می‌شود (پیش‌فرض `admin`). روی سرور اصلی چیزی بگذارید که فقط خودتان بدانید. ورود عادی کارکنان با کد پیامکی و فقط برای حساب فعالِ موجودِ `is_staff` است؛ ورود با گذرواژه فقط مسیر اضطراریِ سوپریوزر است. برای OTP محدودیت ارسال و تلاش ناموفق اعمال می‌شود؛ در مسیر اضطراریِ گذرواژه، بعد از ۵ تلاش غلط برای یک شماره یا ۱۰ تلاش از یک آدرس در ساعت، ورود یک ساعت بسته می‌شود.

- **کتاب‌ها:** اول کتاب را بسازید (نام، نویسنده، ویرایش، عکس جلد، «درباره‌ی کتاب»، رشته‌ها، قیمت)، بعد در پایین صفحه‌ی
  همان کتاب فصل‌ها را اضافه کنید: «فصل تازه (خالی)» یا «فصل از فایل». ترتیب، رایگان بودن، انتشار و بایگانی هر فصل همان‌جاست.
- **مدیریت فصل:** درخت فصل (مقدمه، گروه‌ها، بخش‌ها) و برای هر بخش چهار زبانه: جزوه، خلاصه (کارت مرور)، تست‌ها و
  فلش‌کارت‌ها. افزودن، ویرایش، جابه‌جایی، انتقال به بخش دیگر و بایگانی همه همین‌جاست. ویرایشگر نوار ابزار دارد و کنار
  متن، پیش‌نمایش دقیقاً مثل گوشی نشان می‌دهد. تست و فلش‌کارت هم با فرم ویرایش می‌شوند و هم با «متن خام» (همان قالب فایل).
  هر ذخیره همان قاعده‌های فایل را بررسی می‌کند.
- **فایل فصل همیشه به‌روز:** مرجع اصلی سرور است. «دریافت فایل فصل» هر لحظه `chapter.md` کامل را با همه‌ی ویرایش‌های پنل
  می‌دهد (با عکس‌ها، ZIP)، و «دریافت کل کتاب» همه‌ی فصل‌ها را. «ویرایش کل فایل» کل فصل را به شکل همان فایل نشان می‌دهد
  و قبل از ذخیره تغییرات را فهرست می‌کند. بارگذاری فایل هم قبل از اعمال همین فهرست را نشان می‌دهد.
- **نسخه‌ها:** بعد از هر تغییر یک نسخه از کل فصل نگه داشته می‌شود؛ مقایسه با فصل فعلی و بازگرداندن از صفحه‌ی «نسخه‌ها»ی هر فصل.
- **تست‌ها، فلش‌کارت‌ها، بخش‌ها:** فهرست همه، با فیلتر کتاب، فصل، منبع کنکور، سطح، نوع، حوزه، دشواری سنجیده‌شده،
  گزارش خطا و … و جست‌وجو در متن. دکمه‌ی «ویرایش» هر ردیف همان مورد را در «مدیریت فصل» باز می‌کند.
- **داشبورد آمار:** کاربران، فعال‌های هر روز، ثبت‌نام، فروش، خوانندگان هر کتاب و سخت‌ترین تست‌ها.
- **طرح‌های اشتراک:** قیمت و مدت را همان‌جا عوض کنید. قیمت هر کتاب در خود کتاب (محتوا) است.
- **سفارش‌ها:** فقط برای دیدن؛ قابل ویرایش یا حذف نیستند.
- **دسترسی‌های خریداری‌شده:** می‌توانید دستی به کسی کتاب یا اشتراک هدیه بدهید، یا آن را «لغو شده» کنید.
- **گزارش‌های ایراد:** گزارش‌های کاربران از تست‌ها، فلش‌کارت‌ها و متن‌ها.
- **نسخه‌های اپ:** هر نسخه‌ی جدید اندروید را اینجا ثبت کنید (شماره‌ی ساخت، تغییرات، لینک دانلود). اپ‌های قدیمی‌تر
  پیشنهاد به‌روزرسانی می‌بینند. اگر «به‌روزرسانی اجباری» را بزنید، همه‌ی نسخه‌های قدیمی‌تر دیگر به سرور وصل نمی‌شوند و
  فقط صفحه‌ی «وقت به‌روزرسانی است» را می‌بینند. شماره‌ی ساخت همان عدد فایل است (مثلاً ۱۰ برای `limoplus-test-10`) و
  در اپ: پروفایل › پایین صفحه.

## پیامک ورود نمی‌رسد؟

۱. پنجره‌ی سرور را نگاه کنید: `RayganSMS accepted` یعنی پیامک تحویل رایگان شد؛ `SMS (console)` یعنی `SMS_BACKEND`
هنوز `console` است؛ `failed` یعنی رایگان نپذیرفت و دلیلش همان‌جا نوشته شده.
۲. آزمایش مستقیم: `python manage.py send_test_sms 09xxxxxxxxx` دو پیامک می‌فرستد، یکی بدون خط آخر و یکی با خط کد اپ.
اگر فقط اولی رسید، در `backend/.env` بنویسید `OTP_SMS_APP_HASH=False` (پیامک می‌رسد ولی کد را دستی وارد می‌کنید).

## پرداخت (زیبال)

تا وقتی کد مرچنت واقعی ندارید، `ZIBAL_MERCHANT=zibal` (حالت آزمایشی زیبال) بماند؛ این حالت فقط با `DEBUG=True` اجرا می‌شود و روی سرور اصلی پذیرفته نمی‌شود. بعد فقط همین خط را در
`backend/.env` عوض کنید. سرور باید از اینترنت در دسترس باشد تا زیبال بتواند کاربر را برگرداند
(`SITE_DOMAIN` و `SITE_SCHEME`).

## نوشتن و بارگذاری محتوا

راهنمای کامل قالب فایل فصل‌ها، همراه با دستور آماده برای هوش مصنوعی: [`docs/content-format.md`](docs/content-format.md)

بارگذاری: پنل مدیر › کتاب‌ها › صفحه‌ی کتاب › «فصل از فایل» (یا «افزودن فصل از فایل» بالای فهرست کتاب‌ها).
ویرایش بعدی را می‌شود همان‌جا در «مدیریت فصل» انجام داد؛ فایل به‌روز را از «دریافت فایل فصل» بگیرید.

## انتقال به سرور اصلی و دامنه

فقط دو فایل عوض می‌شود:

1. **`backend/.env`**: `SITE_DOMAIN` (مثلاً `api.limoplus.ir`)، `SITE_SCHEME=https`، `DEBUG=False`، `SECRET_KEY` جدید، `DATABASE_URL`، `CORS_ALLOWED_ORIGINS` (آدرس نسخه‌ی وب)، اطلاعات پیامک و `ZIBAL_MERCHANT`.
2. **`app/.env`**: `EXPO_PUBLIC_API_URL=https://api.limoplus.ir`

هیچ آدرس یا رمزی داخل کد نوشته نشده است. فایل‌های `.env` هرگز وارد GitHub نمی‌شوند.
