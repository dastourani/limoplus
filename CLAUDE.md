# LimooKhan (لیموخوان; formerly LimoPlus) — notes for AI agents

The app is called «لیموخوان» everywhere users see it (app name, SMS, panel, covers, share images). Android package
`ir.limookhan.app`, deep-link scheme `limookhan://`. The repo, folders and the internal SMS module keep the old `limoplus` name.

Interactive learning platform for Iranian university students: books per major (field of study), each with a
summary mode and a full-notes mode, plus tests, flashcards and study stats. The owner does not write code; agents
write and test it. The owner reads Persian; user-facing text, admin labels and docs for the owner are in Persian.
Code, identifiers and commit messages are in English.

## Layout

- `backend/` — Django 5.2 + DRF, PostgreSQL. Apps: `apps.accounts` (phone OTP login, device sessions),
  `apps.catalog` (majors, content tree via django-treebeard, banners), `apps.learning` (questions, choices,
  exam sources, flashcards, reports), `apps.study` (the learner's own data: reading progress, bookmarks,
  highlights/notes, Leitner flashcard boxes, timed exams with negative marking, daily activity, stats, offline
  bundles, admin «داشبورد آمار»), `apps.commerce` (subscription plans, orders, Zibal payment, entitlements).
- `app/` — Expo (SDK 58) + TypeScript, one codebase for Android, web (PWA for iPhone users) and desktop browsers.
  Read `app/AGENTS.md` before touching Expo APIs.
- App screens: `app/src/app/` (Expo Router). Tabs in `(tabs)/` (custom RTL bar): home, library (reading,
  bookmarks, notes), stats, profile. Others: welcome (major), login → verify (OTP; session-limit chooser) →
  edit-profile, devices, book (progress, buy, offline download), section (summary/full, highlights and notes,
  bookmark, night mode, font size, watermark, copy limit, offline fallback), quiz (practice, resume, reset,
  report), exam (timed, negative marking) and exam-result, exams (history), flashcards (Leitner, report, share as
  image), buy/[slug] and payment-result (deep link `limookhan://payment-result`), offline, settings (server address).
  Guests can read free parts; `requireLogin()` sends them to login when a feature needs an account.
  Auth state: `src/lib/auth.tsx` (token in expo-secure-store). Offline books: `src/lib/offline.ts`, AES-256-GCM,
  key in the secure store, wiped on sign-out, valid 30 days. Screenshots are blocked app-wide on Android
  (`src/lib/protect.ts`). Dates: `src/lib/jalali.ts`. Lesson Markdown → HTML in `src/lib/renderMarkdown.ts` (KaTeX MathML output, no font files);
  native renders in a WebView (`MarkdownView.tsx`), web straight into the DOM (`MarkdownView.web.tsx`).
- `.github/workflows/android-apk.yml` — builds a test APK on every push to main touching `app/`, published as a
  GitHub prerelease. It is signed with the debug key and allows cleartext HTTP (for laptop testing).
  TODO before store release: real signing key, HTTPS only (remove `usesCleartextTraffic`).
- App updates: `apps.releases` (`AppRelease` in admin). The Android app sends `X-App-Platform`/`X-App-Build`
  (build = CI run number, `EXPO_PUBLIC_APP_BUILD`); `GET app/version/` offers newer builds; builds older than the newest
  required release get HTTP 426 from `MinimumAppVersionMiddleware` and the app shows `UpdateGate`'s full-screen notice.
- Book covers are drawn, not uploaded: one template (`components/BookCover.tsx`) plus a line motif per subject from
  `src/lib/cover.ts` and `src/lib/coverExtra.ts` (generated by `app/scripts/cover-motifs.py`; 37 motifs) — `cover_motif`
  on the book; dark or light by the learner's choice in profile (`lib/coverTheme.ts`). Motif «custom» uses the book's own
  SVG (`cover_drawing`, cleaned to plain shapes by `apps/catalog/drawing.py`). The same code draws the panel's cover
  preview and the «دریافت جلد» PNG through the admin-preview bundle. An uploaded `cover` image wins. Guide for the
  owner (Persian, with an AI prompt for new motifs): `docs/covers.md`.
  Books can be «به‌زودی» (`is_coming_soon`) with «خبرم کن» (`BookWaitlist`).
- Progress is drawn as a lemon (`LemonProgress`, one wedge per item); quiz and exam share `QuizView` (single web view,
  finger-following page drag) and `usePageTurn`. Don't use «·» next to Persian digits (۰ looks like a dot).
- `docker-compose.yml` — local Postgres + backend (mounts `content/` read-only).
- `content/samples/` — sample book in the chapter format; `python manage.py load_samples` loads it.
- `docs/content-format.md` — the chapter Markdown format (Persian) and the prompt for AI content writers.
- Content import: `apps/catalog/importer.py` (admin «کتاب‌ها» › book › «فصل از فایل», with a preview of changes; or
  `manage.py import_chapter`). Items are matched by slug across the whole book and moved, never duplicated; missing items
  are archived.
- Content panel (`apps/catalog/panel.py`, `editing.py`, `exporter.py`): the database is the source of truth; `exporter`
  writes a chapter back as chapter.md (round trip is exact). Every panel edit goes DB → ParsedChapter → change → text →
  parse (all file rules) → `apply_chapter`, then a `ChapterRevision` copy is kept. Slugs of existing items never change in
  the panel. Pages: books (proxy `Book`), «مدیریت فصل» (JS in `static/catalog/panel.js`), whole-file edit, versions.
  The live preview uses the app's own renderer bundled into `static/catalog/limo-preview.js`; after changing
  `renderMarkdown.ts` or `reviewCard.ts`, run `cd app && npm run build:admin-preview` and commit the bundle.
  Question/flashcard/section admin lists are for filtering; their «ویرایش» opens the chapter manager.
- Labels («برچسب‌های متن», `catalog.Label`, admin): one list for boxes in the notes («درسنامه», `:::تعریف … :::`) and parts
  of the summary («چکیده», `تعریف:` + `- ` items), each with a group and one of four looks (formal/note/warn/table).
  Server: `apps/catalog/labels.py` + `summary.py`; app: `src/lib/labels.ts` + `reviewCard.ts` (the list comes with
  every section). Never deleted, only hidden. Tests marked «نقش: تکمیلی» (`Question.is_extra`) don't count for progress
  (`apps/study/progress.py` `core()`).
- Numbered boxes (`Label.numbered`; «مثال», «نمودار»): counted over the chapter («مثال ۳-۵»), never written in the text;
  `:::مثال {#name}` + `[[#name]]` links. Server: `apps/catalog/numbering.py` (section's start counts and book refs sent with
  each section; explanations get `[[#name|text|node]]` filled in). App: `src/lib/numbering.ts`, renderer.
- Plots: a «:::نمودار» box with «تابع:» lines is drawn as SVG by `src/lib/plot.ts` (formulas: `src/lib/expr.ts`, a small
  numeric parser; mathjs was ~1 MB). Checks: `app/scripts/plot-check.ts` (run with esbuild + node; must pass).
- «صندوق تست» (`apps/catalog/inbox.py`): a hidden book (`ContentNode.is_inbox`, never visible, never published) whose one
  section holds pasted tests until the panel moves them (`question.relocate`: one or many, to any section of any book; ids
  stay, a clashing slug in the target book gets «-2», flashcard links outside the target chapter are dropped).
- Access rules live only in `apps/catalog/access.py` (`AccessMap`): visible = node and all ancestors published and
  not archived; readable = visible and (staff, or free node/ancestor, or owned / covered by an active subscription — `owns_book`).
  Every content endpoint must use it.
- TODO before launch: serve paid-content images through an access check (X-Accel-Redirect); today they have
  unguessable content-hash names but are public to anyone with the URL.

## Rules that must hold

- **No secrets or host names in code.** Everything host-specific lives in `backend/.env` and `app/.env`
  (documented in the `.env.example` files). Moving to a real domain must only change those two files.
- **User data is never lost.** No hard deletes of purchases, progress, notes, scores or reports — use
  `is_archived` / soft delete. Every migration must be reversible and must not drop user data. Content edits must
  not break user data: highlights, progress and comments attach to stable ids, not to text.
- **Money is computed only on the server.** The app never sends prices or discount amounts. Payment verification
  compares the verified amount with the order. Wallet balance changes and order payment happen in one atomic
  transaction with row locks.
- **Auth:** phone + SMS code only (no passwords for learners). Codes and session tokens are stored as keyed hashes.
  OTP: 6 digits, 2 min lifetime, 5 attempts, 60 s resend cooldown, 5 codes/hour and 15 wrong guesses/day per
  phone, 20 requests and 30 wrong guesses/hour per IP. Limits are DB counters (`accounts.ratelimit`), shared by
  all processes. Client IP comes from REMOTE_ADDR or the entry added by our own proxies (`TRUSTED_PROXY_COUNT`),
  never the client-supplied part of X-Forwarded-For. The proxy must overwrite X-Forwarded-Proto.
  The SMS is sent after the code is committed. `SMS_BACKEND=console` is refused when DEBUG is off.
  At most `MAX_ACTIVE_SESSIONS` (2) devices per account; a third login must choose one to sign out.
- **Quiz answers are graded on the server**; correct answers are not sent before submission.
- Formulas are LaTeX rendered with KaTeX, always isolated left-to-right inside RTL text.
- Dates shown to users are Jalali (Persian calendar).

## Decided product details

Negative marking on by default in exam mode. Flashcards are key points (title front, point back), not questions,
and link to related questions. Each question has explanation + optional quick solution + alternative view, and
tags: exam sources (many), declared difficulty, measured difficulty (after 30 answers), domain, kind, topic.
Paid books can have free parts (`is_free` on any node). Pricing: single book purchase and monthly subscriptions
(prices editable in admin). Payment gateway: Zibal (`ZIBAL_MERCHANT`, test merchant `zibal` until the real one).
SMS: RayganSMS (`SMS_BACKEND=raygan`) or `console` for development. Banners: several, horizontal scroll, targeted
by major, never inside reading or quiz screens. AI assistant is shown as "coming soon" only.

## Workflow

- Work on a branch and open a pull request; the owner reviews before merge.
- Run before every PR: `cd backend && SECRET_KEY=test DEBUG=True python manage.py test apps` and
  `cd app && npm run typecheck`. Run backend management commands locally with `DEBUG=True`.
  The same backend tests also run on PostgreSQL in CI (`.github/workflows/backend-tests.yml`): SQLite silently skips some
  things PostgreSQL refuses (e.g. `select_for_update` across nullable joins), so payment and locking code must pass there.
- In this cloud environment `npx expo install` cannot reach Expo's version API; pin versions manually and ask the
  owner to run `npx expo install --fix` locally if needed.
- Payment, auth and data-migration changes get an independent review before merge.
